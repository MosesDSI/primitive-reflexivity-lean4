# Structure Injectivity Axiom Leak and CI Enforcement: Retrospective

**Date:** 2026-10-15
**Project:** `PrimitiveReflexivity`, package `LTromino/` (core Lean only, no Mathlib)
**Toolchain:** `leanprover/lean4:v4.33.1`; CI via `leanprover/lean-action@v1` (resolved SHA `24581d74…`), which runs `leanprover-community/axiom-audit` v0.1.2 (SHA `46024e00…`)
**Commits:** `c33732d` (all 208 theorems axiom-free) → `bf11b64` (CI enforcement, this report)

## Summary

LTromino's 208 theorems were confirmed axiom-free locally with `#print axioms`. Two gaps remained between that result and what CI checked:

1. **The CI audit could not detect a regression.** It ran with the default allowlist `[propext, Classical.choice, Quot.sound]`, so a theorem that started depending on `propext` would still pass.
2. **The local audit covered theorems only.** Three declarations generated by Lean itself depended on `propext`, and the theorem-level audit never listed them.

Both gaps are now closed. CI audits every declaration in the package against an empty allowlist, and the generated declarations that carried `propext` are no longer produced.

## 1. The Gap: the default allowlist cannot catch a regression

The `ltromino` job ran `lean-action` with `axiom-audit: true` and no `axiom-audit-allow`, so it used the action's default allowlist:

```yaml
axiom-audit-allow:
  default: "propext,Classical.choice,Quot.sound"
```

This allowlist is correct for a library whose stated trust base is the standard three axioms, which is the case for SimulationExchange and Theta__0_Photon. For LTromino the stated property is stronger: **no axioms at all**. Under the default allowlist, CI cannot tell an axiom-free package from one that has regressed to the standard axioms. For that claim, a green job is a false green.

**Control.** In a scratch copy of the package, one theorem was added and imported from the library root:

```lean
theorem LTromino.leak_control (a b : Nat) : a + b = b + a := by omega
```

`omega` produces a proof that depends on `[propext, Quot.sound]`. Run with the default allowlist, the pinned tool reported:

```
axiom-audit: audited 402 declaration(s) under 'LTromino'; all within the allowlist [propext, Classical.choice, Quot.sound].
exit 0
```

The leak passed. Before this fix, the only check that could catch it was the local `AxiomCheck.lean`, which is not run in CI.

## 2. The Compiler Finding: synthesized injectivity lemmas carry `propext`

Running the same pinned tool on the **unmodified** package with an empty allowlist failed:

```
axiom-audit: 3 declaration(s) under 'LTromino' use disallowed axioms:
  LTromino.WalkerMatrix.mk.injEq → [propext]
  LTromino.Sym.mk.injEq → [propext]
  LTromino.Tromino.mk.injEq → [propext]
allowed: []
exit 1
```

**Cause.**
- When Lean 4.33.1 elaborates a `structure`, it synthesizes two injectivity lemmas for the constructor:
  - `S.mk.inj`: `⟨a…⟩ = ⟨b…⟩ → a = b ∧ …`. A minimal test structure confirms it is axiom-free.
  - `S.mk.injEq`: `(⟨a…⟩ = ⟨b…⟩) = (a = b ∧ …)`. This is an equality *between propositions*. Proving it uses `propext`, and the same test confirms `[propext]`.
- LTromino declares three structures, so the environment held six synthesized lemmas, three of which depended on `propext`:
  - `Sym` (`Base.lean`), with `deriving DecidableEq`;
  - `Tromino` (`Tiling.lean`), with `deriving DecidableEq`;
  - `WalkerMatrix` (`WalkerBridge.lean`), with `deriving DecidableEq`.

**Why the theorem-level audit missed them.**
- `AxiomCheck.lean` is generated from the `theorem` declarations in the five source files, so it lists 208 names. The synthesized lemmas are not written in the source and never appear there.
- axiom-audit walks every declaration in the library's modules: definitions, instances, generated equation lemmas and these injectivity lemmas. That was 406 declarations.
- So the two audits measured different things:

| Measure | Scope | Result before the fix |
|---|---|---|
| Theorem purity (`AxiomCheck.lean`) | 208 user-written theorems | 208/208 axiom-free |
| Environment purity (axiom-audit, empty allowlist) | 406 declarations | 403/406; 3 synthesized `mk.injEq` use `propext` |

None of the 208 theorems uses an `injEq` lemma; that is why theorem purity held. The earlier `simp`-based `Equivariance.lean` used `Tromino.mk.injEq`, but the axiom-free rewrite in `c33732d` does not.

## 3. The Remediation

### 3a. Stop synthesizing the injectivity lemmas

`set_option genInjectivity false in` is placed before each structure's doc comment. Placed between the doc comment and `structure`, it is a parse error.

```lean
set_option genInjectivity false in
/-- A symmetry: `s` swaps the coordinates, then `a` flips x and `b` flips y. -/
structure Sym where
  s : Bool
  a : Bool
  b : Bool
  deriving DecidableEq
```

The same change is applied to `Tromino` and `WalkerMatrix`.

**Effects:**
- Neither `S.mk.inj` nor `S.mk.injEq` is generated; a test structure reports both names as unknown constants. Six declarations are removed, and the total goes from 406 to 400.
- `deriving DecidableEq` still works, because the derived instance does not depend on these lemmas.
- No theorem statement, definition body or proof changed. The diff is three added lines.

**Constraint for future work:** proofs about these three structures cannot call `S.mk.inj` or `S.mk.injEq`. Constructor equalities must be handled with `congrArg`, `rw`, `show`/`rfl`, or `cases` on the equation, which is what the current proofs already do.

### 3b. Enforce an empty allowlist in CI

```yaml
  ltromino:
    ...
      - uses: leanprover/lean-action@v1
        with:
          lake-package-directory: LTromino
          leanchecker: true
          axiom-audit: true
          # Empty allowlist: every LTromino declaration must depend on no axioms.
          # axiom-audit drops blank entries, so "," parses to []; a bare "" could be
          # replaced by the action's default allowlist.
          axiom-audit-allow: ","
```

**Why `","` and not `""`:**
- `lean-action`'s `run_axiom_audit.sh` passes the input through unchanged as `--allow "$AXIOM_AUDIT_ALLOW"`.
- axiom-audit's `parseNames` splits on `,`, trims each part and drops empty entries. Both `""` and `","` therefore parse to `[]` at the tool level.
- The open question was the GitHub layer: whether an explicitly empty `with:` input reaches the action as `""` or is replaced by the input's `default`. `","` is a non-empty string, so no default can replace it, and the tool still reads it as the empty list.
- The CI log prints the effective allowlist, so the result can be checked from the log (see §4).

The other CI jobs keep the default allowlist, because their stated trust base is the standard three axioms. `theta-0-photon` was not touched.

## Lessons

- An axiom allowlist audit only proves what its allowlist excludes. A zero-axiom claim needs an empty allowlist in CI, plus a planted control that shows the check can fail.
- A theorem-level `#print axioms` audit does not cover the environment. Compiler-synthesized declarations (`mk.injEq`, and potentially other generated lemmas) are invisible to a list built from source `theorem` lines. They can carry axioms no user proof introduced, so the environment-wide tool is the authoritative check.
- When an input's empty value could be ambiguous across layers (GitHub input defaults versus tool parsing), pass a value that is unambiguous at every layer and confirm it from the printed result.
